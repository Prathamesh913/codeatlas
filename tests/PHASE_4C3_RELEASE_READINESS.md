## 3. What Is Genuinely Production-Ready

- **The pipeline itself** (collect → annotate → structure → investigate → resolve →
  consolidate → canonicalize → project): deterministic, isolated outputs, read-only on
  repositories, zero runtime dependencies, graceful exit codes.
- **Trustworthiness machinery**: no silent deletion (demotions recorded with misleading
  strings), decision-complete logs (`consolidations.json`, `canonical-report.json`,
  VOI logs with `would_resolve_with`), ambiguity preserved, confidence enums,
  `naming_evidence` with rejected candidates, technical names as aliases/`implementation_terms`.
- **The canonical map format**: `INDEX.md` is navigable without internal reports
  (features/systems by name+aliases, technical→canonical mapping, file→entity index,
  unresolved listing); per-entity pages carry description, files, relationships,
  provenance, evidence.
- **Test infrastructure**: 194 tests incl. end-to-end runs on two unfamiliar-style
  fixtures (React/TS app, Python CLI) asserting no source mutation, determinism, and
  projection completeness.

## 4. What Is Ready for Private Beta

- Running the pipeline over a **JavaScript/TypeScript or Python repository** and consuming
  `canonical/*.json` + `markdown/` (see caveat §8.3 on non-JS/Py stacks).
- The CinePrint-class experience: user-facing feature names, evidence-grounded
  descriptions, query index, unresolved/ambiguous visibility.
- Agent consumption via `SKILL.md` (current, 524 lines, all stages documented with
  behavioral rules).

## 5. What Blocks Public Beta

1. **README is stale and misleading** — frozen at Phase 2C: states the CLI and scanner
   "do not exist", documents no installation or usage, promises `flows.json` in examples
   (never generated by the pipeline). An outsider cannot adopt the tool from the README.
2. **No unified CLI** — the pipeline is 7 separate `node src/<stage>/cli.js` invocations
   with ordered directory arguments and no `codeatlas` entry command, no `--help` beyond
   usage strings, no `--version`.
3. **Packaging not publication-safe** — `npm pack` ships 205 files / 883 kB including all
   tests and fixtures; no `files` whitelist; `license: "TBD"`; version 0.3.0 disagrees
   with module versions (0.4.0–0.4.3 and 0.1.0×3).

## 6. What Blocks Stable npx Release

Everything in §5, plus:
- **No version control**: the working directory is **not a git repository** — no commit
  history, no tags, no reproducible release state. This is a hard blocker for any
  published artifact.
- Unfamiliar-repository validation is still thin (2 synthetic smoke fixtures; both
  validated but small) — a stable release needs a broader real-repository tour.
- Failure ergonomics: the canonical stage surfaces raw stack traces on bad input
  (exit code correct; message not user-shaped).

## 7. Critical Issues

1. **No git repository** (process/release blocker, not a code defect).
2. **README contradicts reality** (claims the tool has no CLI/scanner) — an outsider
   following it would conclude CodeAtlas is vaporware.
3. None in core correctness or trustworthiness: no critical code defect was found.

## 9. Recommended Release Stage

## 11. Is Another Semantic Architecture Phase Justified?

**No.** The 4C.0→4C.3 arc resolved the measured failure classes (relative imports, UI
string taxonomy, relevance gating, fragmentation/conflation, naming authority, VOI,
projection). Remaining semantic gaps are recorded, bounded, and carry explicit
resolution paths (image/poster-data tension, server-infra, PD naming, inspection ≤50%).
None is release-blocking for a private beta; all have provenance and would-resolve-with
paths. A further architecture phase would refactor ahead of evidence.

## 12. Should Packaging and Documentation Become the Primary Focus?

**Yes.** The limiting factor on adoption is now the gap between what the pipeline does
(validated, deterministic, transparent) and what an outsider can discover from the
repository surface (stale README, no unified CLI, no git, TBD license, no files
whitelist). The next body of work should be productization: git, README, CLI unification,
packaging metadata, regenerated examples — then private beta feedback, not semantic
refactoring.
